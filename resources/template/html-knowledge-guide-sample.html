DNS — Domain Name System

Learn how a name such as example.com becomes an IP address that a computer can use to communicate with a server.

What is DNS?

DNS is a distributed naming system used to map domain names to information such as IP addresses.

Why do we need it?

Humans prefer names. Networks communicate using addresses. DNS connects the two.

Simple example

You type: example.com

DNS helps your system discover the corresponding address.

Big idea: DNS is like a distributed directory for Internet names.
USER ↓ BROWSER ↓ DNS QUERY ↓ DNS SERVER ↓ IP ADDRESS ↓ SERVER ↓ RESPONSE

DNS Fundamentals

Start with the problem DNS solves.

Names vs addresses

Human Computer network
example.com IP address
Easy to remember Used for network communication

Common DNS records

Record Purpose
A Maps a name to an IPv4 address.
AAAA Maps a name to an IPv6 address.
CNAME Creates an alias to another domain name.
MX Specifies mail-server information.
TXT Stores text information used by many systems.
Note: DNS does much more than simply return an IP address. Different record types support different use cases.

How DNS Works

Follow one DNS lookup from your computer to the answer.

YOU TYPE https://example.com ↓ LOCAL CACHE ↓ DNS RESOLVER ↓ ROOT DNS ↓ .COM TLD DNS ↓ AUTHORITATIVE DNS ↓ IP ADDRESS ↓ YOUR COMPUTER

Step 1 — Ask the resolver

Your system normally sends the DNS request to a configured recursive resolver.

Step 2 — Resolver finds the answer

If the resolver does not already have a valid cached answer, it can query the DNS hierarchy.

Step 3 — Result is returned

The resolver returns the DNS answer to the client.

Key takeaway: The browser usually does not directly walk the entire DNS hierarchy. A recursive resolver performs that work on behalf of the client.

DNS Architecture

DNS is hierarchical and distributed.

DNS ROOT │ ┌──────────────┼──────────────┐ ↓ ↓ ↓ .com .org .net │ ↓ AUTHORITATIVE DNS │ ↓ example.com │ ↓ DNS RECORD │ ↓ IP ADDRESS

Recursive Resolver

Finds answers for clients and commonly caches them.

Root Servers

Provide referrals toward the authoritative infrastructure for top-level domains.

TLD DNS

Handles top-level domains such as .com, .org and .net.

Authoritative DNS

Provides the authoritative records for a domain.

DIY DNS Lab

Inspect DNS behavior directly from your computer.

Linux / macOS

dig example.com
dig example.com A
dig example.com MX

Windows

nslookup example.com
nslookup -type=MX example.com
What to observe: Look at the query, answer, TTL, server used and returned records.

DNS Debugging

Troubleshoot DNS systematically instead of guessing.

APPLICATION ↓ OS DNS CONFIG ↓ NETWORK ↓ DNS RESOLVER ↓ AUTHORITATIVE DNS ↓ DNS RECORD

Useful checks

ipconfig /all
nslookup example.com
ping example.com
tracert example.com
Important: A successful DNS lookup does not prove that the destination application is healthy. DNS, routing, transport and application layers can fail independently.

Interview / KT Q&A

Q: What is DNS?

DNS is a distributed naming system that maps domain names to information such as IP addresses.

Q: Is DNS the Internet?

No. DNS is one service used by Internet-connected systems.

Q: What is DNS caching?

A DNS result can be stored temporarily so future queries can be answered without repeating the complete lookup.

Glossary

Term Simple meaning
DNS Domain Name System.
Resolver System that obtains DNS answers for clients.
TTL Time-to-live associated with cached DNS information.
Authoritative Providing the official DNS data for a domain.
Record A DNS data entry such as A, AAAA or MX.
