# Coding Standards

## Overview

Coding standards establish a common engineering language across teams. Consistent code is easier to understand, review, test, maintain, and extend. High-performing engineering organizations prioritize readability and maintainability over individual coding style.

## Definition

Coding standards are a set of agreed engineering conventions that govern how software is written, organized, documented, reviewed, and maintained.

They improve collaboration, reduce defects, and lower the long-term cost of software ownership.

## Objectives

- Improve code readability.
- Reduce maintenance effort.
- Increase development consistency.
- Simplify code reviews.
- Enable scalable team collaboration.

## Core Principles

- Readability over cleverness.
- Consistency over personal preference.
- Simplicity before optimization.
- Small, focused functions and classes.
- Meaningful naming.
- Self-documenting code.
- Minimize duplication.
- Fail fast with clear error handling.

## Best Practices

- Follow language-specific style guides.
- Keep methods focused on a single responsibility.
- Write descriptive commit messages.
- Keep pull requests small and reviewable.
- Prefer automated formatting and static analysis.
- Continuously refactor while preserving behavior.

## Common Mistakes

- Inconsistent naming conventions.
- Large methods and classes.
- Excessive comments instead of clear code.
- Copy-paste programming.
- Ignoring linting or static analysis warnings.
- Mixing business logic with infrastructure concerns.

## Interview Focus

Be prepared to explain how coding standards improve software quality, team productivity, onboarding, maintainability, and long-term engineering velocity.
