# C++ Basics - Knowledge Check

This document contains interview-focused questions and concise, production-oriented answers for quick revision.

---

# Topic 1 - Why C++ Exists

## Q1. Why was C++ created if C already existed?

**Answer:**

C++ was created to overcome the limitations of C when developing large and complex software systems. While C provides excellent performance and direct hardware access, it lacks features such as classes, encapsulation, inheritance, and polymorphism that improve code organization and maintainability.

C++ extends C by adding these capabilities while preserving its performance and low-level control.

---

## Q2. If C++ has classes, why wasn't a completely new language created instead of extending C?

**Answer:**

Extending C allowed developers to reuse existing code, tools, libraries, and expertise instead of starting from scratch. It also made migration easier because organizations could gradually adopt C++ while continuing to use their existing C code.

---

## Q3. Why would AMD choose C++ over Java for GPU drivers?

**Answer:**

GPU drivers require direct hardware access, deterministic performance, low latency, and manual control over memory. C++ provides these capabilities, whereas Java runs on the JVM and abstracts hardware details, making it unsuitable for low-level system software such as device drivers.

---

## Q4. If Java is slower because of the JVM, why are many enterprise applications still written in Java instead of C++?

**Answer:**

The choice depends on the requirements.

Enterprise applications usually prioritize maintainability, developer productivity, portability, and safety over maximum performance. Java provides automatic memory management, a rich ecosystem, and strong runtime support, making it a better fit for many business applications.

---

## Q5. Name three advantages of Java over C++.

**Answer:**

- Automatic garbage collection.
- Better memory safety with no direct pointer manipulation.
- Rich ecosystem and strong productivity for enterprise application development.

---

## Q6. What is Zero-Cost Abstraction?

**Answer:**

Zero-Cost Abstraction means that if you don't use a language feature, you don't pay any runtime cost for it. If you do use the feature, it should generate code that is nearly as efficient as writing the low-level implementation manually.

---

# Topic 2 - Compilation Process

## Q1. Does the compiler directly convert a `.cpp` file into an executable?

**Answer:**

No.

The C++ build process consists of four stages:

- Preprocessor
- Compiler
- Assembler
- Linker

The linker produces the final executable after combining object files and required libraries.

---

## Q2. Arrange the following in the correct order.

- Source Code
- Preprocessor
- Compiler
- Assembler
- Object File
- Linker
- Executable

**Answer:**

```text
Source Code
    ↓
Preprocessor
    ↓
Compiler
    ↓
Assembler
    ↓
Object File
    ↓
Linker
    ↓
Executable
```

---

## Q3. Why does C++ use multiple build stages instead of directly generating an executable?

**Answer:**

Each stage has a specialized responsibility. This separation makes the build process easier to maintain, supports incremental builds, improves scalability, and reduces build time by allowing unchanged object files to be reused.

---

## Q4. Does the compiler understand `#include`?

**Answer:**

No.

The preprocessor processes `#include`, expands the contents of the header file, and passes the resulting source code to the compiler.

---

## Q5. What happens internally when we write `#include <iostream>`?

**Answer:**

Before compilation, the preprocessor replaces the `#include` directive with the contents of the appropriate header file. The compiler then compiles the expanded source code as if the header contents were written directly in the source file.

---

## Q6. Why is conditional compilation useful for a company like AMD?

**Answer:**

Large software projects often support multiple operating systems, hardware platforms, and product variants. Conditional compilation allows only the required code to be compiled for the target platform, reducing build time, executable size, and unnecessary dependencies.

---

## Q7. If compilation fails, can the linker still create an executable?

**Answer:**

No.

The linker depends on the object files generated by the compiler and assembler. If compilation fails, the required object files are not created, so the linker cannot produce an executable.

---

## Q8. Suppose you write:

```cpp
int age = "AMD";
```

Who reports the error first?

- Preprocessor
- Compiler
- Linker
- Operating System

**Answer:**

The **Compiler**.

The compiler performs syntax checking and type checking. Since a string literal cannot be assigned to an integer variable, it reports a type mismatch during compilation.

---

## Q9. The compiler is responsible for __________ but NOT responsible for __________.

**Answer:**

**Responsible for:**

- Syntax checking
- Type checking
- Generating assembly code

**Not responsible for:**

- Expanding `#include`
- Processing macros
- Linking object files

---

## Q10. Why are compilation errors generally easier to debug than runtime errors?

**Answer:**

Compilation errors are detected before the program runs and usually point directly to the source code causing the problem. Runtime errors occur while the program is executing, often depend on specific inputs or environments, and can be much harder to reproduce and debug.

---

## Q11. Can object files be executed directly?

**Answer:**

No.

An object file is an intermediate output generated by the assembler. It contains machine code but is incomplete because external symbols and libraries have not yet been resolved. The linker combines object files and required libraries to produce the executable.

---

## Q12. AMD has 5000 `.cpp` files, but only `logger.cpp` changed today. Why is the object-file approach better than recompiling all 5000 files?

**Answer:**

Only `logger.cpp` needs to be recompiled into a new object file. The remaining object files can be reused, and the linker combines them to produce the executable.

This significantly reduces build time, improves developer productivity, speeds up CI/CD pipelines, and provides faster feedback.

---

## Q13. The assembler is responsible for __________ but NOT responsible for __________.

**Answer:**

**Responsible for:**

- Converting assembly code into object files
- Generating machine code
- Producing intermediate object files for the linker

**Not responsible for:**

- Preprocessing source files
- Type checking
- Linking object files into an executable

---

## Q14. Why do large companies invest so much effort into improving build times?

**Answer:**

Faster builds improve the entire software development lifecycle.

They provide quicker feedback to developers, reduce CI/CD execution time, speed up testing and releases, improve engineering productivity, and reduce infrastructure costs.

---

## Q15. If compilation succeeds, can we guarantee that an executable will be created?

**Answer:**

No.

Compilation success only means the source code was successfully converted into object files. The linker must still resolve all symbols and combine the required object files and libraries. If linking fails, no executable is produced.

---

## Q16. Suppose `main.cpp` calls `calculateSalary()`, but its implementation is missing. Who reports the error?

- Compiler
- Assembler
- Linker
- Operating System

**Answer:**

The **Linker**.

The compiler only verifies that the function is declared correctly. During linking, the linker searches for the function's implementation. If it cannot find it, it reports an **undefined reference** (or unresolved external symbol) error.

---

## Q17. The linker is responsible for __________ but NOT responsible for __________.

**Answer:**

**Responsible for:**

- Combining object files
- Resolving external symbols
- Producing the final executable

**Not responsible for:**

- Preprocessing source files
- Compiling source code
- Generating object files

---

## Q18. Why are linker errors generally more difficult to debug than compilation errors?

**Answer:**

Linker errors often involve multiple source files, libraries, build configurations, and dependencies. In large projects with many teams, identifying the missing or incorrect symbol can take significantly more effort than fixing a compilation error in a single source file.

---

# Topic 3 - Variables

## Q1. Why do Modern C++ developers care so much about an object's lifetime and ownership?

**Answer:**

Modern C++ gives developers explicit control over resources such as memory, files, sockets, and locks. Knowing who owns a resource and how long it lives prevents memory leaks, dangling pointers, double deletion, and other resource management issues. Concepts such as RAII and smart pointers are built on these principles.

---

# Topic 4 - References

## Q1. What will be the output?

```cpp
int age = 36;

int& years = age;

years = 50;
```

What are the values of `age` and `years`?

**Expected Interview Answer:**

```cpp
age = 50
years = 50
```

A reference is another name (alias) for an existing object. Both `age` and `years` refer to the same memory location, so modifying one changes the same underlying object.

---

## Q2. Why are references better than copying large objects?

**Expected Interview Answer:**

References avoid creating unnecessary copies of large objects. This reduces memory usage, improves performance, and makes function calls more efficient. They are widely used in production code when multiple components need access to the same object without creating duplicates.

---

## Q3. Will this compile?

```cpp
int& age;
```

**Expected Interview Answer:**

No.

A reference must be initialized when it is declared because it must always refer to an existing valid object.

---

## Q4. What happens here?

```cpp
int age = 36;

int salary = 100;

int& years = age;

years = salary;
```

What are the values after execution?

**Expected Interview Answer:**

```cpp
age = 100
salary = 100
years = 100
```

`years` is still a reference to `age`.

The statement:

```cpp
years = salary;
```

copies the value of `salary` into `age`. It does **not** make `years` refer to `salary`.

---

## Q5. What does this function communicate?

```cpp
void processData(Data& data);
```

**Expected Interview Answer:**

This API communicates that:

- A valid object is required.
- No copy will be created.
- The function may modify the object.
- The caller retains ownership of the object.

---

## Q6. Which is more expensive?

```cpp
Employee employee2 = employee1;
```

or

```cpp
Employee& employee2 = employee1;
```

Why?

**Expected Interview Answer:**

```cpp
Employee employee2 = employee1;
```

is more expensive because it creates a new object by copying the existing one.

```cpp
Employee& employee2 = employee1;
```

creates only another name for the same object without allocating additional memory or performing a copy.

---

## Q7. Complete the sentence.

References are frequently used in Modern C++ because _______________________.

**Expected Interview Answer:**

References provide efficient access to existing objects without unnecessary copying. They improve performance, reduce memory usage, and make APIs cleaner and easier to understand.

---

## Q8. Which declaration communicates:

> "I promise not to modify your object."

```cpp
Employee

Employee&

const Employee&
```

**Expected Interview Answer:**

```cpp
const Employee&
```

It provides read-only access to an existing object while avoiding unnecessary copying.

---

## Q9. Suppose `GPUInfo` is a 100 MB object.

Which design would you choose?

```cpp
void process(GPUInfo info);

void process(GPUInfo& info);

void process(const GPUInfo& info);
```

Requirements:

- Modification is NOT required.
- Performance is important.

**Expected Interview Answer:**

```cpp
void process(const GPUInfo& info);
```

because:

- No modification is required.
- No object copy is created.
- Large objects are passed efficiently.
- The API clearly communicates read-only access.

---

## Q10. Complete the sentence.

`const T&` is heavily used in Modern C++ because ____________________________.

**Expected Interview Answer:**

`const T&` provides efficient read-only access to an existing valid object without unnecessary copying. It improves performance while clearly communicating that the object will not be modified.

---

```cpp
void generateReport(GPUInformation ? info);
```

Options:

```cpp
GPUInformation

GPUInformation&

const GPUInformation&
```

Requirements:

- Modification is NOT required.
- Performance is important.
- `GPUInformation` is a large object.

**Expected Interview Answer:**

```cpp
const GPUInformation&
```

because it satisfies all three requirements:

- Read-only access
- No copying
- Better performance

---

## Q12. Why is `const T&` heavily used in Modern C++ APIs?

Use only these concepts:

- Valid object
- Read-only access
- Performance
- API design
- No copying

**Expected Interview Answer:**

Many APIs only need to read an existing object. Using `const T&` communicates that the object must be valid, will not be modified, and will not be copied. This improves performance and makes the API's intent clear.
