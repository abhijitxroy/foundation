# Documentation

## Overview

Documentation preserves engineering knowledge, improves collaboration, accelerates onboarding, and reduces long-term maintenance costs. Well-written documentation enables teams to understand systems, make informed decisions, and evolve software with confidence.

## Definition

Documentation is the structured recording of technical knowledge, decisions, processes, architecture, APIs, operational procedures, and engineering practices throughout the software lifecycle.

Good documentation explains the intent behind a system—not just its implementation.

## Objectives

- Share knowledge effectively.
- Reduce dependency on individuals.
- Improve maintainability.
- Support onboarding.
- Enable faster troubleshooting and decision making.

## Documentation Lifecycle

```text
Requirements
      │
      ▼
Design Decisions
      │
      ▼
Implementation
      │
      ▼
API & User Documentation
      │
      ▼
Operational Documentation
      │
      ▼
Continuous Updates
```

## Types of Documentation

| Type | Purpose |
|------|---------|
| Requirements | Capture business and technical needs. |
| Architecture | Explain system structure and design decisions. |
| API | Describe interfaces, contracts, and usage. |
| Code | Clarify intent where code alone is insufficient. |
| Operational | Support deployment, monitoring, recovery, and maintenance. |
| Decision Records (ADR) | Preserve important architectural decisions and trade-offs. |
| User Documentation | Help end users effectively use the product. |

## Best Practices

- Document the "why" before the "how".
- Keep documentation close to the source.
- Update documentation alongside code changes.
- Prefer concise, accurate, and maintainable documents.
- Use diagrams where they improve understanding.
- Remove obsolete documentation promptly.

## Common Mistakes

- Documentation that becomes outdated.
- Documenting implementation details instead of intent.
- Over-documenting obvious code.
- Keeping critical knowledge only in meetings or chats.
- Treating documentation as a one-time activity.

## Interview Focus

Be prepared to explain how good documentation improves engineering velocity, onboarding, incident response, architecture evolution, and long-term maintainability.
